Experimental Debugging

How does experimental debugging help us test an idea about the cause of an error?

Experimental debugging resembles the scientific method: form a hypothesis about the cause, change a small part, run the program again, and check whether the result supports the hypothesis.

Experimental Debugging Cycle
1. ObserveSee the error or unexpected output.
2. HypothesizeIdentify a possible cause.
3. ChangeModify a small part.
4. RunExecute the program again.
5. CheckCompare the result with the hypothesis.
6. RepeatContinue until the behavior is correct.

The Collatz 3n + 1 Sequence

How does the Collatz rule use repetition and decisions to transform a number until it reaches 1?

Start with a positive integer n. If n is even, replace it with n//2; if n is odd, replace it with 3*n+1. Repeat until n reaches 1.

Python
n = 12
steps = 0
while n != 1:
    print(n, end=", ")
    if n % 2 == 0:
        n = n // 2
    else:
        n = 3 * n + 1
    steps += 1
print(n)
print("Total steps:", steps)
Expected output
12, 6, 3, 10, 5, 16, 8, 4, 2, 1
Total steps: 9

APPENDIX

Quick Revision & Good Practices

Remember

  • Program = instructions for a task.
  • Debugging = finding and fixing bugs.
  • Syntax, runtime and semantic errors are different.
  • Expressions produce values.
  • = assigns; == compares.
  • for is useful for definite iteration.
  • while repeats while a condition is true.
  • break exits; continue skips.
  • Paired data can be grouped in tuples.
  • Functions can receive arguments and return values.

Do

  • Use meaningful variable and function names.
  • Follow snake_case.
  • Use comments to explain why.
  • Keep 4-space indentation consistent.
  • Break large problems into small functions.
  • Test edge cases.

Don't

  • Don't use vague names unnecessarily.
  • Don't use unexplained magic numbers.
  • Don't mix tabs and spaces.
  • Don't write overly long functions.
  • Don't ignore error messages.
